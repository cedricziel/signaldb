# design-sync notes (SignalDB UI)

- [GENERAL] src/ui is an app, not a published package. `.design-sync/pkg/build.sh` (cfg.buildCmd) builds a stand-in library: tsc emits .d.ts for all of src/ui/src (tests, stories, testFixtures excluded), and esbuild bundles an entry into `.design-sync/pkg/dist/`. Components = every `src/components/*.tsx` with a sibling story (automatic). Pages = the PAGES list (`Export:path`), exported by name; a new page story needs a PAGES line plus a `titleMap` entry keyed by the title's last segment with spaces removed ("Pages/API Keys" -> "APIKeys").
- [GENERAL] `pkg/tsconfig.json` emits .d.ts for all of src/ui/src except tests and story helpers. Story/test helpers not named `*.stories.tsx` (`features/evals/evalStories.tsx`, `features/evals/testUtils.tsx`) failed declaration emit with TS2742 (inferred type references storybook/vitest internals), so the exclude list also covers `**/testUtils.tsx` and `**/*Stories.tsx`. A helper with another name needs its own line.
- [GENERAL] build.sh mirrors vite `define` globals (`__SIGNALDB_*__`); a new define in vite.config.ts must be added there too, or esbuild leaves it as an undefined reference.
- [GENERAL] React Query context: the storybook decorator's QueryClientProvider (and story-local `@tanstack/react-query` imports) otherwise bundle a separate copy, so components see "No QueryClient set". Fix: the bundle exports QueryClient/QueryClientProvider/previewQueryClient, `cfg.provider` wraps with them, and `cfg.storyImports.shim: ["@tanstack/react-query"]` routes story imports to the bundle.
- [GENERAL] Story wrappers bundle any module they import that isn't a bundle export (route trees, story helpers), and those modules import shared runtime. So `react-router`, `@tanstack/react-query`, `api/gen/client.gen`, `api/http` and `lib/pwaUpdate` are shimmed to the bundle (storyImports.shim) and re-exported IN FULL from it (`export *` in build.sh's RUNTIME_DTS). Otherwise contexts and state split into two copies: "useNavigate() may be used only in the context of a <Router>", `ds_exports.useParams is not a function`, an unstubbed API client, a ThrottleBanner that never sees the throttle, or an UpdateBanner whose card renders empty (validate `[RENDER] root empty`). A new story that seeds module-level state from a `lib/` module needs the same two lines. Editing `storyImports` re-keys every component's grade, so expect a full re-grade after it.
- [GENERAL] Any stylesheet whose module no bundle export reaches never ships (story-local CSS compiles empty), so stories that render such modules preview unstyled. build.sh imports those stylesheets explicitly (shell + `features/schema/SchemaExplorer.css`, which only `schema/routes.tsx` reaches - SchemaHub "Storage Explorer" previewed unstyled tables until it was added). Check on each sync: every `src/ui/src/**/*.css` should appear in `dist/index.css`'s `/* path */` comments.
- [GENERAL] The shell's stylesheets (UserMenu.css, AppNav.css, …) must be imported in build.sh's entry right after global.css: story-local CSS compiles empty, and before `AppShell` was an export the shell story previewed an unstyled nav (bare links) after #1753 retired TopBar (which used to carry shell styles). Keep the explicit imports so the order stays pinned. A new shell stylesheet needs a line there too. Order matters and must mirror the app's import order: UserMenu.css BEFORE AppNav.css (AppNav.tsx imports UserMenu first) - reversed, `.user-menu { margin-left: auto }` beats the sidebar variant's reset and right-aligns the account row.
- [GENERAL] build.sh imports global.css FIRST in the entry, matching main.tsx. Loaded last, its `.btn` rules override feature CSS of equal specificity (e.g. `.mobile-filters-toggle {display:none}`), so the mobile Filters button showed at desktop width.
- All pages use cardMode single + viewport 1280x800 (primaryStory = the light default). Don't switch pages to "column": a column card renders every story at once, and each story installs its own fetch stub, so stories overwrite each other's data (SchemaHub threw on `.trim()` of undefined). Consent/Manage also use fixed overlays that no grid can hold. Every page's `Dark` story is still captured and graded one at a time; at the default capture width they fall under the 900px breakpoint and collapse the sidebar.
- Page stories carry no size of their own: every `Pages/*`/`Shell/*` story renders in `stories/PageFrame.tsx` (`pageFrame`: 100% wide x 100vh, `growingPageFrame` for Overview/Catalog/Evals: 100% wide, min 100vh), so the capture viewport alone decides the layout. At 1280x800 `pageFrame` draws the same 1280x800 box the old fixed `<div style={{ width: 1280, height: 800 }}>` wrappers did; a card whose viewport is narrower than 900 now shows the page's real mobile layout instead of a clipped 1280px page. Don't reintroduce fixed-size wrappers: `pnpm test:stories` (docs/contributing/ui-page-stories.md) checks every page story at 390/768/1280.
- Components styled by a feature stylesheet they don't import: MemberTable (Populated) and StacktraceLines (Trace Variant) rely on `features/traces/traces.css`; QueryError (`.query-error`) and MobileSidebarDrawer (`.mobile-filters-toggle`) rely on `features/explore/explore.css`. Storybook renders them without those styles; the preview (bundle carries all CSS) matches the real app. Graded against the app (MemberTable/StacktraceLines match, QueryError and MobileSidebarDrawer Interactive Toggle close). Fixing it in the repo means importing the stylesheet from each component.
- Dialog's single card: the `.ds-single` wrapper contains the fixed backdrop, so the panel renders at the top instead of centred. Framing, graded match.
- SidebarResizer: both sides are blank (the handle is transparent until hover). A real match, not a blank render.
- SemanticKey story title → export `SemanticKeyLabel` (titleMap).
- Skipped (render nothing in storybook either): ThrottleBanner Hidden (returns null; its card shows Visible only, since both stories share one throttle state), UpdateBanner Hidden (same, sharing the pending-update state), MobileSidebarDrawer OpenByDefault/RightSide (drawer is mobile-only CSS), SemanticKey Unresolved (renders null without semantics), SourceSnippet Unavailable (gated off with no seeded probe).
- ConfirmButton/SourceSnippet: owned previews replay the story `play` click after mount (storybook shows post-play state).
- BrandMark: an unsized svg that fills its container; the owned preview puts it in a 240px box. validate flags it `[RENDER_THIN]` (no text, svg only) - benign, accepted.
- ServiceGraph uses `cardMode: "column"`: its maps are wider than a grid cell (`[GRID_OVERFLOW]` on NarrowContainer).
- `AppShell` (`features/shell/AppShell.tsx`) is the app frame as a component: `App` supplies the identity and tenant state, the shell only draws. It syncs from the `Shell/App Shell` story into its own `shell` group (PAGES line in build.sh, `overrides.AppShell`). Outside a router it mounts its own MemoryRouter at `page`, which is how designs use it; the `Blank Page` story covers that path. build.sh also exports `previewWhoami` (the stories' `sampleWhoami()`) so designs can fill the account row. `.design-sync/conventions.md` tells the design agent to put every screen inside `AppShell` and never draw its own nav: keep its page-id list in step with `navModel.ts`. ExploreView no longer has a card (its old `Pages/App Shell` story rendered the whole App).
- The design project also holds hand-made files outside the sync's paths (`templates/`, `screenshots/`, `previews/`, `design_handoff_overview_and_nav/`, `_adherence.oxlintrc.json`). The upload's write/delete globs never touch them; keep it that way.
- Eval pages (`Pages/Evals/*`: AgentsScoresView, RunsView, CompareView, CaseView, EvaluatorsView, EvalSetsView, EvalSetView) sync in the `evals` group, single cards like the other pages. AgentsScoresView needs `viewport: 1280x1000`; at 900 the card clipped the last evaluator row. EvalSetView (`Pages/Evals/Eval Set`, titleMap `EvalSet`) is registered at 1280x1000 for its 12-case table; its story wraps the view to pass `name`, since the page reads it from the route. Both eval-set stories answer `/api/v1/eval-sets…` from `EVAL_SET_LIST`/`EVAL_SET_DETAILS` in `evalFixtures.ts` (not captured by design-sync yet).
- The build logs an esbuild `import.meta` warning from react-router's dev-only `import.meta.hot` check; it evaluates to undefined in the iife bundle and is harmless.
- OverviewView (`Pages/Overview`) is ~1590px tall at 1280 wide: `viewport: 1280x1650` (1500 cropped the ingest chart). Its fixture (`overviewIr` in the story) answers every IR query from the request's own `range`, so a frozen-clock capture stays consistent.
- [FONT_MISSING] JetBrains Mono / Cascadia Code are fallback entries in the `--mono` system stack; the app ships no webfonts, so the system fonts are the real design (accepted).
- Framing: the storybook canvas paints `--bg` behind stories; the preview pages are white (except `Dark` stories, whose DarkScope darkens `<html>`). That's a harness difference, not a component one.

## Re-sync risks

- RealUsersView (`Pages/Real Users`) is newly registered; its `1280x1000` viewport was checked against real Playwright screenshots of the Default/Setup/Dark stories (not a design-sync capture) — Default's content is ~740px tall, Setup's ~940px, so 1000 has slack on both and shouldn't clip; raise it if the page grows in a later group.
- CatalogView's card shows EntityDetail at 1280x2000: the service overview page is ~2000px tall. If it grows further, raise the viewport or the card clips (the preview stops mid-page while the storybook side shrinks to fit).
- Story fixtures that feed time series must derive timestamps from the request's own range (fetchStub `bodyFor`), in nanoseconds like the real IR; Date.now()/ms-scale fixtures render as a spike then flat.
- Dark mode: every page has a `Dark` story (DarkScope → scoped `data-theme="dark"` that fills the frame, plus `data-theme="dark"` on `<html>` while mounted so the page behind any overflow is dark too; before, it only covered its content and dark captures showed a light band below), graded like the rest; Traces also has `Trace Detail Dark`; components are only checked in light on sync (the Storybook toolbar covers them manually).
- Play-driven stories render their pre-play state in previews (graded close): PasswordForm ErrorState, Catalog Map View Node Selected (side panel opens on click), Traces Trace Map (Map view selected by click). Processors TestRun looks identical on both sides at 800px tall (graded match). Only ConfirmButton/SourceSnippet have owned previews that replay the click.
- The Processors pages are only partly styled in the app itself (processors-table/-title/-subtitle/-note/-button/-row-actions are defined in no stylesheet); the previews faithfully copy that.
- Owned previews (ConfirmButton, SourceSnippet, BrandMark) mirror story exports by name. Renaming or adding stories needs them updated.
- build.sh's COMPONENTS/PAGES lists and define globals are hand-maintained.
- AttributeTable (7), ServiceGraph (14) and CatalogView (9) exceed the default 6-story capture cap; all three were captured with `--max-stories 14` so the map stories are graded; pass it again when those components change.
- Fresh clone = no local grades (`.design-sync/.cache/` is gitignored). The driver's churn canary then keeps picking ungraded churned components, and every re-run adds new ones to `pendingGrade`. Capture the whole `verification.canary.churned` list in one scoped `compare.mjs --components ...` run, grade it, then re-run the driver.
- Toolchain: the pinned Node is in the repo-root `.nvmrc` (24.19.0); cloud containers default to Node 20/22 and may not have nvm (download the nodejs.org tarball and put its `bin` on PATH). Use it before `pnpm i`, build.sh, the storybook build and the driver. Chromium: `DS_CHROMIUM_PATH=/opt/pw-browsers/chromium-*/chrome-linux/chrome`.
